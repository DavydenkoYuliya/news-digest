# AI Дайджест новин

Щоночі збирає зовнішні новини з RSS, оцінює їх за допомогою AI для відділу закупівель і публікує статичний сайт:

- **Головне сьогодні** — найважливіші події по закупівлях і по конкурентах;
- **Новини** — стрічка з фільтрами;
- **Ринок закупівель** — короткі довідки по категоріях закупівель і напрямах (висновок → факти з посиланнями → деталі);
- **Конкуренти** — брифінг по 5 світових виробниках м'яса птиці.

Нові дані з'являються щоночі, до початку робочого дня. На сайті немає серверної частини, ключів і даних користувачів — лише готові файли.

**Документи:** [бізнес-логіка і промпти](docs/1-biznes-logika.md) · [архітектура в 5 розрізах](docs/2-arhitektura.md)

## Як це працює

```
python run.py   (щоночі; дані готові до початку робочого дня)
  1. збір RSS (feeds/)                       → прибирання повторів
  2. AI: оцінка за заголовками → детальний розбір релевантних
  3. конкуренти: відбір за списками компаній (competitors.yaml, regex) + переклад
  4. AI: брифінг конкурентів, довідки по категоріях
  5. site/public/data/digest.json + site/public/competitor_brief.html
cd site && npm run build   → статичні файли сайту в site/build
```

## Структура

| Що | Де |
|---|---|
| Запуск | `run.py` |
| Налаштування (без програміста) | `config.yaml` |
| Ключ і вибір AI | `.env` (шаблон — `.env.example`) |
| Інструкції для AI (методика) | `prompts/*.md` |
| Джерела новин | `feeds/*.txt` |
| Конкуренти: компанії, бренди, профілі, категорії подій (без програміста) | `competitors.yaml` |
| Код | `digest/` |
| Сайт (React; збирання — Vite) | `site/` |
| Дані для сайту | `site/public/data/` (формат — нижче, «Файл даних сайту») |
| Документи для ІТ і бізнесу | `docs/` |
| Перевірки | `tests/` |
| Нічний запуск на GitHub | `.github/workflows/digest.yml` |

## Запуск локально

```bash
pip install -r requirements.txt
cp .env.example .env        # вписати LLM_API_KEY
python -m unittest discover tests   # перевірки без AI і без інтернету
python run.py --dry-run     # весь конвеєр без AI (без витрат)
python run.py               # справжній запуск
cd site && npm ci && npm run build   # сайт → site/build (Node 22)
npm test                    # перевірка сайту
```

## Вибір AI

У `.env`:

| LLM_PROVIDER | Що ще задати |
|---|---|
| `anthropic` (за замовчуванням) | `LLM_API_KEY`, `LLM_MODEL=claude-haiku-4-5` |
| `openai` | `LLM_API_KEY`, `LLM_MODEL=<модель>`; `pip install openai==2.54.0` |
| `azure` | `LLM_API_KEY`, `LLM_MODEL=<deployment>`, `AZURE_OPENAI_ENDPOINT`; `pip install openai==2.54.0` |

Код звертається до AI лише через `digest/llm.py`, тож зміна провайдера — це зміна `.env`.

**Перевірено лише на Claude** (`anthropic`, модель `claude-haiku-4-5`) — на ньому працює щоденний запуск і проведено перевірку якості. Варіанти `openai` і `azure` написані, але ще жодного разу не запускалися. Перед переходом на них потрібен пробний запуск і порівняння якості: інструкції для AI (`prompts/`) налаштовано під Claude.

## Передача в ІТ і розміщення

### Коротко

- Один нічний пакетний запуск (≈ 20 хв) і статичний сайт. Немає бази даних, серверних функцій і входу користувачів.
- Один секрет — ключ AI.
- Вартість AI — $0,30–0,60 за ніч (модель `claude-haiku-4-5`), тобто $10–15 на місяць із запасом на ручні перезапуски.
- GitHub Actions: ≈ 20 хв × 22 робочі дні ≈ 450 хв на місяць.
- Python 3.12, Node 22. Версії бібліотек зафіксовані: `requirements.txt`, `site/package-lock.json`.

### Варіант A — корпоративний GitHub (рекомендовано, ≈ 1–2 год)

1. Створити репозиторій в організації і залити поточні файли — без історії особистого репозиторію.
2. **Settings → Secrets and variables → Actions:** секрет `LLM_API_KEY` (корпоративний ключ). За потреби змінні (Variables): `LLM_PROVIDER`, `LLM_MODEL`, `AZURE_OPENAI_ENDPOINT`.
3. **Settings → Pages → Source:** «GitHub Actions».
4. **Settings → Actions → General:** дозволити Actions; *Workflow permissions* — «Read and write permissions» (нічний запуск зберігає щоденні дані в репозиторій). Використовуються лише офіційні модулі `actions/*`.
5. Якщо гілка `main` захищена правилами (обов'язковий перегляд змін), додати GitHub Actions до винятків (*bypass*) — інакше нічний запуск не зможе зберегти дані.
6. **Actions → «AI Дайджест новин» → Run workflow.** Через ≈ 20 хв перевірити сайт (адреса — у Settings → Pages).
7. Дати власниці методики права *Write*: вона змінює налаштування через веб-інтерфейс GitHub (див. «Хто що змінює»).

### Варіант B — власний сервер

- Встановити Python 3.12 і Node 22; `pip install -r requirements.txt`; у `site/` — `npm ci`.
- Ключ AI — змінна середовища `LLM_API_KEY` або файл `.env` (шаблон — `.env.example`).
- Щоночі (cron або Планувальник завдань), після 00:00 за Києвом:
  ```bash
  python run.py && cd site && npm run build
  ```
- Вміст `site/build/` віддавати як статичні файли будь-яким вебсервером. Шляхи відносні — сайт працює з будь-якої папки чи адреси.
- Між запусками зберігати `site/public/data/`, зокрема `daily/` (7 останніх днів; потрібні для прибирання повторів, старші видаляються автоматично).

### Мережевий доступ (вихідний)

| Для чого | Адреси |
|---|---|
| Джерела новин | `news.google.com` (245 з 252 стрічок), `oilprice.com`, `gcaptain.com`, `marinelink.com`, `railfreight.com`, `trans.info`, `severe-weather.eu`, `woah.org` |
| AI | `api.anthropic.com` (для `openai` — `api.openai.com`, для `azure` — ваш `*.openai.azure.com`) |
| Лише варіант B, під час встановлення | `pypi.org`, `files.pythonhosted.org`, `registry.npmjs.org` |

Корпоративний проксі, що підміняє сертифікати: `collect.verify_ssl: false` у `config.yaml`.

### Щоденна перевірка і збої

- **Запуск пройшов:** у репозиторії з'являється запис «Дані <дата>», на сайті в «Головне сьогодні» оновлюється період.
- **Запуск упав:** GitHub надсилає лист тому, хто останнім змінював розклад (`cron`) у `.github/workflows/digest.yml`, — тож варто, щоб це був відповідальний в ІТ. Сайт тим часом показує дані попереднього запуску, нічого не ламається.
- **Що зупиняє запуск:** лише недоступність AI на етапі оцінки новин (немає ключа, вичерпано кошти, збій сервісу). Збій окремого джерела, перекладу чи однієї довідки запуск не зупиняє — довідка замінюється переліком новин.
- **Перезапуск:** Actions → «AI Дайджест новин» → Run workflow (повний прогін, $0,30–0,60).

### Хто що змінює

| Що | Хто | Як |
|---|---|---|
| `config.yaml`, `competitors.yaml`, `prompts/`, `feeds/` | власниця методики (закупівлі) | напряму, у веб-інтерфейсі GitHub; діє з наступної ночі |
| `digest/`, `site/`, `run.py`, `.github/` | ІТ (або за запитом власниці методики) | через Pull Request; перевірки — `tests/` і `npm test` |
| ключ AI, доступи, оновлення бібліотек | ІТ | після оновлення бібліотек — пробний запуск |

### Відомі обмеження

- **Перевірено лише на Claude** — див. «Вибір AI».
- AI-тексти іноді мають мовні огріхи. Числа, валюти й посилання на джерела перевіряються автоматично, стиль — ні.
- 245 з 252 стрічок — запити до Google News: у Reuters, Bloomberg та галузевих платних видань немає відкритих RSS, а прямий парсинг їхніх сайтів заблокований. Повного тексту статей немає — лише заголовок і фрагмент. Якщо Google обмежить запити з серверів (GitHub чи корпоративних), новин стане значно менше.
- Розклад GitHub Actions може запізнюватися на кілька годин; дані готові «до початку робочого дня».

## Файл даних сайту (`digest.json`)

Сайт читає один файл — `site/public/data/digest.json`; його щоночі пише `run.py`. Це «договір» між нічним запуском і сайтом: новий розділ сайту бере дані звідси, нове поле додається сюди. Якщо зміна несумісна з попереднім форматом (поле перейменовано чи прибрано), збільшити `SCHEMA_VERSION` у `run.py`.

| Поле | Що в ньому |
|---|---|
| `schema_version` | версія формату файлу (зараз `2`) |
| `generated` | коли сформовано (UTC, ISO 8601) |
| `period` | період новин, напр. `02.10–06.10.2026` |
| `model`, `prompt_version` | модель AI і версія інструкцій для довідок |
| `domains` | напрями з `config.yaml`: `{ключ: {name, icon}}` — назва на сайті та іконка |
| `min_news` | з якої кількості новин створюється довідка |
| `items[]` | стрічка новин (див. нижче) |
| `market[]` | «Ринок закупівель»: групи `{group, entries[]}`; запис — `{key, label, ids[], brief}` |
| `today` | «Головне сьогодні»: `{proc[], comp[]}` |

**`items[]` — одна новина:**

| Поле | Що в ньому |
|---|---|
| `n` | номер новини в цьому файлі; на нього посилаються довідки (`refs`, `ids`) |
| `section` | `news` — загальні новини, `competitor` — новини конкурентів |
| `date` | дата публікації (UTC, ISO 8601) |
| `source`, `url` | джерело і посилання на оригінал |
| `title` | заголовок на сайті: AI-резюме українською (якщо його немає — переклад або оригінал) |
| `summary`, `detailed` | AI-резюме / детально (факти з новини) |
| `domain` | ключ напряму з `domains` |
| `category` | категорії закупівель через кому (зі списку `config.yaml`) |
| `country`, `commodity` | країни; група сировини/товару (у конкурентів порожні) |
| `score` | важливість 1–10 |
| `company` | для конкурентів — коротка назва компанії (`label` з `competitors.yaml`) |

**`market[].entries[].brief`** — довідка або `null` (замало новин чи не пройшла перевірку — тоді сайт показує перелік новин `ids`):
`verdict` (висновок), `why[]` (чому це важливо), `facts[]` і `events[]` (`{text, refs[]}`; у подій ще `type`, `confidence` = `hi|mid|lo`, `key` — чи йде в «Головне сьогодні»), `related[]` (`{text, ref}`), `badge` (`{text, tone}`), `no_news`, `profile` (профіль категорії з `config.yaml`), `model`, `prompt_version`.

**`today`:** `proc[]` — головні події по закупівлях (`{t, m, conf, go, refs[]}`: текст, підпис, впевненість, ключ запису в `market`, номери новин); `comp[]` — головне по конкурентах (рядки тексту).

Поруч лежать `competitor_brief.html` (брифінг конкурентів, готова сторінка) і `daily/news_<дата>.json` (новини кожного дня; потрібні лише нічному запуску для прибирання повторів, сайт їх не читає).

## Безпека

- Єдиний секрет — ключ AI; лише в `.env` або секретах CI, у репозиторій не потрапляє.
- Сайт статичний: без серверних функцій і без звернень до AI з браузера.
- На сайті лише загальнодоступна інформація: новини з відкритих джерел (RSS) і AI-зведення до них. Внутрішніх даних компанії немає, тому окремий вхід на сайт не потрібен.
- Сайт не збирає даних користувачів: лише вибрані фільтри запам'ятовуються в браузері самого користувача.
- Перевірка SSL увімкнена; вимкнути (`collect.verify_ssl: false`) лише для корпоративного проксі, що підміняє сертифікати.

## Якість AI-довідок

- Класифікація новин — відповідь вільним текстом з JSON (зі схемою Haiku пише тексти гірше — перевірено сліпим тестом); напрям і категорія після відповіді звіряються зі списками `config.yaml`.
- Довідки по категоріях — відповідь у заданій структурі (JSON Schema).
- Кожен факт у довідці має посилання на новину стрічки.
- Числа, яких немає в тексті джерела, не публікуються (`digest/guardrails.py`); довідка, що не пройшла перевірку, замінюється переліком новин.
- Якщо новин у категорії менше `category_briefs.min_news`, довідка не створюється.
- Біля кожної довідки — модель і версія інструкції.
