# AI Дайджест новин — інструкція з переносу для ІТ

**Що це:** нічний Python-скрипт, який збирає зовнішні новини з RSS, оцінює їх за допомогою AI для відділу закупівель і публікує статичний сайт. Немає бази даних, серверних функцій, входу користувачів і персональних даних. Один секрет — ключ AI.

**Скільки роботи:** варіант A (корпоративний GitHub) — 1–2 години; варіант B (власний сервер) — від пів дня до дня.

Пов'язані документи: [2-biznes-logika.md](2-biznes-logika.md) — що і навіщо робить кожен крок; [3-arhitektura.md](3-arhitektura.md) — схеми в 5 розрізах; [README](../README.md) — структура, запуск, формат даних.

## 2. Варіант A — корпоративний GitHub (рекомендовано)

**A1. Репозиторій.** Створити репозиторій в організації (наприклад, `news-digest`), розпакувати архів і завантажити файли:

```bash
git init -b main
git add -A
git commit -m "AI Дайджест новин: перенос"
git remote add origin https://github.com/<організація>/news-digest.git
git push -u origin main
```

**A2. Ключ AI.** *Settings → Secrets and variables → Actions → New repository secret*: `LLM_API_KEY` = корпоративний ключ.
За потреби там же, вкладка *Variables*: `LLM_PROVIDER` (`anthropic` | `openai` | `azure`), `LLM_MODEL`, `AZURE_OPENAI_ENDPOINT`.

**A3. Публікація сайту.** *Settings → Pages → Build and deployment → Source*: **GitHub Actions**.
Якщо сайт має бути доступний лише працівникам — у GitHub Enterprise Cloud: *Pages → Visibility: Private*. Вміст сайту — загальнодоступна інформація, тому це не обов'язково.

**A4. Дозволи нічного запуску.** *Settings → Actions → General*:
- *Actions permissions*: дозволити (використовуються лише офіційні модулі `actions/checkout`, `setup-python`, `setup-node`, `configure-pages`, `upload-pages-artifact`, `deploy-pages`);
- *Workflow permissions*: **Read and write permissions** — нічний запуск зберігає щоденні дані в репозиторій.

**A5. Захист гілки `main`** (якщо в організації обов'язковий перегляд змін): додати *GitHub Actions* до винятків правила (*bypass list*). Інакше крок «Зберегти дані в репозиторії» не пройде.

**A6. Перший запуск.** *Actions → «AI Дайджест новин» → Run workflow → main*. Триває ≈ 20 хв.

**A7. Приймання** — див. розділ 5.

**A8. Доступи.** Власниці методики — роль *Write*: вона правитиме `config.yaml`, `competitors.yaml`, `prompts/`, `feeds/` через веб-інтерфейс GitHub.

**A9. Сповіщення про збої.** Лист про невдалий нічний запуск GitHub надсилає тому, хто **останнім змінював рядок `cron`** у `.github/workflows/digest.yml`. Щоб листи отримував відповідальний в ІТ, йому варто зробити цей коміт (наприклад, змінити коментар біля `cron`).

**Розклад:** Пн–Пт о 22:00 UTC (01:00 за Києвом влітку, 00:00 взимку). GitHub може стартувати із затримкою до кількох годин; користувачам обіцяємо оновлення «до початку робочого дня».

## 3. Мережевий доступ (вихідний HTTPS)

| Для чого | Адреси |
|---|---|
| Джерела новин | `news.google.com` (262 з 269 стрічок), `oilprice.com`, `gcaptain.com`, `www.marinelink.com`, `railfreight.com`, `trans.info`, `www.severe-weather.eu`, `www.woah.org` |
| AI | `api.anthropic.com` · для `openai` — `api.openai.com` · для `azure` — ваш `*.openai.azure.com` |
| Лише варіант B, під час встановлення | `pypi.org`, `files.pythonhosted.org`, `registry.npmjs.org` |

Корпоративний проксі, що підміняє сертифікати: у `config.yaml` → `collect.verify_ssl: false` (лише в цьому випадку). Проксі задається стандартними змінними `HTTPS_PROXY` / `HTTP_PROXY`.

## 4. Варіант B — власний сервер

**B1. Встановити** Python 3.12 і Node 22.

**B2. Розпакувати** пакет у робочу папку (наприклад, `D:\news-digest` або `/opt/news-digest`) і встановити залежності:

```bash
pip install -r requirements.txt
cd site && npm ci && cd ..
```

**B3. Ключ AI** — змінна середовища `LLM_API_KEY`, або файл `.env` у робочій папці (шаблон `.env.example`; доступ до файлу — лише для служби запуску).

**B4. Перевірка без AI і без витрат:**

```bash
python -m unittest discover tests
python run.py --dry-run
```

**B5. Нічний запуск** — щоночі після 00:00 за Києвом, Пн–Пт:

Linux (`crontab -e`):
```
0 1 * * 1-5  cd /opt/news-digest && python run.py && cd site && npm run build && rsync -a --delete build/ /var/www/news-digest/
```

Windows (Планувальник завдань, дія — `cmd /c`):
```
cd /d D:\news-digest && python run.py && cd site && npm run build && robocopy build C:\inetpub\news-digest /MIR
```

**B6. Вебсервер** (IIS, nginx або Azure Static Web Apps) віддає вміст `site/build/` як статичні файли. Шляхи відносні — сайт працює з будь-якої адреси чи підпапки.

**B7. Не стирати між запусками** `site/public/data/` — там 7 останніх днів для прибирання повторів (старші файли видаляються автоматично).

**B8. Сповіщення про збої:** код виходу `run.py` ≠ 0 означає збій — підключити до вашого моніторингу.

## 5. Приймання (перший запуск)

| Перевірка | Як | Очікується |
|---|---|---|
| Запуск пройшов | Actions → останній запуск (або код виходу на сервері) | усі кроки зелені / код 0 |
| Дані збережено | у репозиторії | коміт «Дані <дата>», оновлено `site/public/data/digest.json` |
| Сайт відкривається | адреса з *Settings → Pages* (або вашого вебсервера) | 4 вкладки: Головне сьогодні, Новини, Ринок закупівель, Конкуренти |
| Дані свіжі | вкладка «Головне сьогодні» | період закінчується сьогоднішньою датою |
| Стрічка | вкладка «Новини» | ≈ 200–300 новин за 3 дні, кожен напрям — своя іконка |
| Довідки | вкладка «Ринок закупівель» | довідки по категоріях з ≥ 5 новинами, біля кожної — модель і версія інструкції |
| Конкуренти | вкладка «Конкуренти» | брифінг по 5 компаніях з датою генерації |

## 6. Експлуатація

**Що зупиняє запуск:** лише недоступність AI на етапі оцінки новин — немає ключа, вичерпано кошти або ліміти, збій сервісу. Сайт тоді показує дані попереднього запуску, нічого не ламається.

**Що НЕ зупиняє:** недоступне окреме джерело, збій перекладу, довідка, що не пройшла перевірку (замість неї показується перелік новин).

| Симптом | Імовірна причина | Що зробити |
|---|---|---|
| Крок «Нічний запуск» червоний, у журналі `[FATAL] Не задано LLM_API_KEY` | немає секрету | крок A2 |
| `[FATAL] … 0 статей пройшло фільтр score` або помилки 401 / 429 від AI | ключ недійсний, вичерпано кошти чи ліміти | перевірити ключ і баланс у консолі провайдера AI |
| Крок «Зберегти дані в репозиторії» червоний | захищена гілка `main` | крок A5 |
| Крок публікації червоний | *Pages → Source* не «GitHub Actions» | крок A3 |
| Новин помітно менше, у журналі багато `0 entries` | джерела недоступні з мережі / Google обмежує запити | перевірити мережевий доступ (розділ 3) |
| Нічний запуск упав після правки налаштувань | помилка у `config.yaml` / `competitors.yaml` (відступи) | відкотити останній коміт (*History → Revert*) або виправити |

**Перезапуск:** *Actions → «AI Дайджест новин» → Run workflow* (повний прогін, ≈ $0,30).

**Оновлення бібліотек:** версії зафіксовані (`requirements.txt`, `site/package-lock.json`). Після оновлення — `python -m unittest discover tests`, `cd site && npm test`, один ручний запуск.

**Перехід на OpenAI / Azure:** змінні `LLM_PROVIDER`, `LLM_MODEL` (для Azure — назва deployment), `AZURE_OPENAI_ENDPOINT`; бібліотека `openai==2.54.0` ставиться автоматично. Перед переходом — пробний запуск і порівняння якості з Claude на тих самих новинах.
