Діаграми записані у форматі Mermaid: GitHub показує їх як картинки прямо в цьому файлі.

| № | Розріз | На яке питання відповідає |
|---|---|---|
| 1 | [Бізнес-контекст](#1-бізнес-контекст) | Хто користується, звідки дані, що отримує бізнес |
| 2 | [Процес (нічний конвеєр)](#2-процес-нічний-конвеєр) | Що відбувається з новиною від джерела до сайту |
| 3 | [Компоненти](#3-компоненти) | З яких частин складається код і налаштування |

| 5 | [Безпека, доступи і зміни](#5-безпека-доступи-і-зміни) | Секрети, мережа, ролі, як зміна потрапляє в робочу версію |

## 1. Бізнес-контекст

Інструмент щоночі перетворює сотні зовнішніх новин на коротку ситуативну картину для закупівель: що змінилося на ринках сировини, у логістиці, санкціях, погоді та у світових конкурентів. Внутрішні дані компанії не використовуються.

```mermaid
flowchart LR
    subgraph SRC["Відкриті джерела"]
        GN["Google News<br/>245 тематичних запитів<br/>(Reuters, Bloomberg… — без власних RSS)"]
        SITES["Галузеві сайти<br/>oilprice, gCaptain, MarineLink,<br/>RailFreight, trans.info, WOAH…"]
    end

    AI["AI-сервіс<br/>Claude Haiku<br/>(оцінка, резюме, довідки, переклад)"]

    TOOL["AI Дайджест новин<br/>нічний запуск"]

    SITE["Сайт<br/>Головне сьогодні · Новини ·<br/>Ринок закупівель · Конкуренти"]

    subgraph USERS["Користувачі"]
        PROC["Закупівлі<br/>категорійні менеджери"]
        MGMT["Керівництво"]
    end

    OWNER["Власниця методики<br/>налаштування, інструкції AI, джерела"]
    IT["ІТ<br/>розміщення, ключ AI, доступи"]

    GN --> TOOL
    SITES --> TOOL
    TOOL <--> AI
    TOOL --> SITE
    SITE --> PROC
    SITE --> MGMT
    OWNER -. "config.yaml, competitors.yaml,<br/>prompts/, feeds/" .-> TOOL
    IT -. "підтримка" .-> TOOL
```

**Межі рішення.** Тільки зовнішня ситуативна інформація, тільки читання. Немає внутрішніх даних, рекомендацій «що робити», обліку користувачів, бази даних і серверної частини.

## 2. Процес (нічний конвеєр)

Одна команда `python run.py`, далі збирання сайту. Цифри — типовий день (одна доба збору).

```mermaid
flowchart TD
    A["Крок 1: Збір RSS<br/>54 стрічки загальних новин<br/>за останню добу"] --> B
    B["Крок 2: Шум і повтори (без AI)<br/>• рубрики-агрегатори (Morning Bid…)<br/>• повтори з 2 попередніми днями<br/>• повтори в межах дня<br/>• спорт, кіно, гороскопи…"] --> C
    C["Крок 3: AI, етап 1 — лише заголовки<br/>бал 1–10, дешево"] --> D{"бал ≥ 4?"}
    D -- ні --> X["відкинуто"]
    D -- так --> E["Крок 4: AI, етап 2 — повний розбір<br/>бал, напрям, категорія закупівель,<br/>країна, сировина, резюме, факти"]
    E --> F["Крок 5: Звірка зі списками config.yaml<br/>(напрям і категорія — лише з довідника)"]
    F --> G{"бал ≥ 4?"}
    G -- ні --> X
    G -- так --> H["Новини дня: 100–150<br/>daily/news_дата.json (зберігається 7 днів)"]

    K["Конкуренти (паралельна гілка)<br/>стрічки 5 компаній → відбір за словами<br/>competitors.yaml (regex) → фільтр біржового шуму<br/>→ AI лише перекладає"]

    H --> L["Крок 6: Зведення за 3 дні + конкуренти<br/>одна подія з кількох джерел = один рядок"]
    K --> L
    L --> M["Крок 7: AI: довідки «Ринок закупівель»<br/>по категоріях і напрямах, де ≥ 5 новин"]
    M --> N{"Перевірка:<br/>числа й валюти є в джерелі?<br/>посилання на реальні новини?"}
    N -- так --> O["довідка"]
    N -- "ні, після 2 спроб" --> P["замість довідки —<br/>перелік новин"]
    K --> Q["Крок 8: AI: брифінг конкурентів<br/>по кожній компанії + «головне»"]
    O --> R["Крок 9: «Головне сьогодні»<br/>без AI — з готових довідок"]
    Q --> R
    R --> S["Крок 10: digest.json + competitor_brief.html"]
    S --> T["Крок 11: Збирання сайту (Vite)<br/>→ 3 статичні файли + дані"]
    T --> U["Крок 12: Публікація (GitHub Pages)"]
```

Деталі «чому саме так» — у [1-biznes-logika.md](1-biznes-logika.md).

## 3. Компоненти

```mermaid
flowchart LR
    subgraph CFG["Налаштування (без програміста)"]
        C1["config.yaml<br/>пороги, напрями й іконки,<br/>категорії, профілі категорій"]
        C2["competitors.yaml<br/>компанії, бренди, мінус-слова,<br/>профілі, категорії подій"]
        C3["prompts/*.md<br/>інструкції для AI (методика)"]
        C4["feeds/*.txt<br/>джерела новин"]
        C5[".env / секрети CI<br/>провайдер AI, ключ, модель"]
    end

    subgraph PY["Python: digest/ + run.py"]
        RUN["run.py<br/>порядок кроків"]
        RSS["rss.py · collect.py<br/>читання стрічок"]
        DED["dedup.py<br/>повтори"]
        CLS["classify.py · commodity.py<br/>AI-оцінка в 2 етапи"]
        CMP["competitors.py<br/>відбір конкурентів, шум, переклад"]
        CB["competitor_brief.py<br/>брифінг конкурентів (HTML)"]
        BR["category_briefs.py<br/>довідки «Ринок закупівель»"]
        GR["guardrails.py<br/>перевірка чисел, валют, посилань"]

        ST["store.py<br/>щоденні файли, digest.json"]
        LLM["llm.py<br/>єдина точка звернення до AI:<br/>anthropic | openai | azure"]
    end

    subgraph WEB["Сайт: site/ (React, збирання — Vite)"]
        W1["useDigestData.js<br/>читає digest.json"]
        W2["вкладки: Головне сьогодні,<br/>Новини, Ринок закупівель, Конкуренти"]
    end

    DATA["site/public/data/<br/>digest.json, daily/,<br/>competitor_brief.html"]

    C4 --> RSS
    C2 --> CMP
    C2 --> CB
    C1 --> CLS
    C1 --> BR
    C3 --> LLM
    C5 --> LLM
    RUN --> RSS --> DED --> CLS
    RUN --> CMP --> CB
    RUN --> BR --> GR
    RUN --> TD
    CLS --> LLM
    CMP --> LLM
    CB --> LLM
    BR --> LLM
    RUN --> ST --> DATA
    DATA --> W1 --> W2
```

| Частина | Обсяг | Хто змінює |
|---|---|---|
| Налаштування (`config.yaml`, `competitors.yaml`, `prompts/`, `feeds/`) | ≈ 1 450 рядків тексту (з них ≈ 640 — списки джерел) | власниця методики |
| Python (`run.py`, `digest/`) | ≈ 2 000 рядків | ІТ, через Pull Request |
| Сайт (`site/src/`) | ≈ 2 300 рядків (з оформленням) | ІТ, через Pull Request |
| Перевірки (`tests/`, `site/src/App.test.jsx`) | 13 автотестів | ІТ |

Формат `digest.json` (договір між нічним запуском і сайтом) описаний у [README](../README.md#файл-даних-сайту-digestjson).

## 4. Розгортання

### Варіант A — корпоративний GitHub (рекомендовано)

```mermaid
flowchart LR
    subgraph GH["GitHub організації"]
        REPO["Репозиторій<br/>код + налаштування + щоденні дані"]
        SEC["Секрети<br/>LLM_API_KEY"]
        ACT["GitHub Actions<br/>Пн–Пт ≈ 01:00 Київ, ≈ 20 хв"]
        PAGES["GitHub Pages<br/>статичний сайт"]
    end
    NEWS["Google News,<br/>галузеві сайти"]
    LLMAPI["api.anthropic.com"]
    BROWSER["Браузер користувача"]

    REPO --> ACT
    SEC --> ACT
    ACT -- "читає RSS" --> NEWS
    ACT -- "звернення до AI" --> LLMAPI
    ACT -- "дописує дані дня" --> REPO
    ACT -- "публікує зібраний сайт" --> PAGES
    BROWSER -- "відкриває" --> PAGES
```

Серверів немає: запуск іде на машинах GitHub, сайт — на GitHub Pages.

### Варіант B — власний сервер


## 5. Безпека, доступи і зміни

### Секрети, мережа, дані

```mermaid
flowchart TB
    subgraph IN["Що потрібно інструменту"]
        K["1 секрет — ключ AI<br/>лише в секретах CI або .env,<br/>у репозиторій не потрапляє"]
        N["Вихідний доступ:<br/>news.google.com + 7 галузевих сайтів,<br/>api.anthropic.com"]
    end
    subgraph NOT["Чого немає"]
        N1["бази даних"]
        N2["серверних функцій"]
        N3["входу користувачів і персональних даних"]
        N4["звернень до AI з браузера"]
        N5["внутрішніх даних компанії"]
    end
    subgraph SITE["Сайт"]
        S1["лише статичні файли для читання"]
        S2["фільтри запам'ятовуються тільки<br/>в браузері самого користувача"]
    end
    IN --> SITE
```

Залежності: 0 відомих вразливостей (`npm audit`, `pip-audit`, жовтень 2026). Модулі нічного запуску — лише офіційні `actions/*`.

### Ролі

| Роль | Що робить | Доступ |
|---|---|---|
| Власниця методики (закупівлі) | інструкції для AI, налаштування, джерела, конкуренти | *Write* у репозиторії |
| ІТ | розміщення, ключ AI, доступи, оновлення бібліотек, зміни коду | *Admin* |
| Користувачі | читають сайт | лише адреса сайту |

### Як зміна потрапляє в робочу версію

```mermaid
flowchart LR
    I["Ідея / правка<br/>(власниця методики)"] --> T["Тестовий стенд<br/>особистий репозиторій,<br/>ручний запуск, свій сайт"]
    T --> C{"Результат<br/>влаштовує?"}
    C -- ні --> I
    C -- так --> P["Перенос у корпоративний<br/>репозиторій<br/>(налаштування — напряму,<br/>код — Pull Request через ІТ)"]
    P --> NIGHT["Наступна ніч:<br/>робочий сайт оновлено"]
```

Зміни йдуть тільки в один бік: тестовий стенд → корпоративна версія.
